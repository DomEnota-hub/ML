# MediaLoader: обязательный регламент CI

Актуальный источник: docs/ci/README.md. Старый порядок сборки отменён. Рабочая база разработки — feature/ml-17211-simple-archive-replacement (PR #172); инфраструктура уже интегрирована. Не переносить изменения на main и не публиковать релиз без отдельной приёмки. Версия 1.7.211/271 забракована на устройстве (VerifyError); не распространять её.

Единственный штатный маршрут CI приложения — .github/workflows/ml-ci.yml.
**Промежуточные коммиты, открытие и обновление PR не запускают CI/Gradle.** Только явный workflow_dispatch либо одна метка ci:verify, ci:qualify или ci:quick-<profile> (baseline/archive/privacy/navigation/library/playback/editors/download/storage/diagnostics). Метки взаимоисключающие. Quick через dispatch допускает объединение профилей (quick_profiles, через запятую) и quick_lint; через метку один профиль. Профиль всегда включает базовый набор, проверки доступа, точный inventory ID/XML, свежие JVM/Compose workers; неизвестный профиль/лишние или пропущенные ID/неожиданный skip/дублированные маркеры блокируют результат. Quick не даёт qualification receipt.
По решению владельца 24.11.2026 каждый этап требует компиляции изменённых компонентов и адресной регрессии изменённых и зависимых компонентов, обязательных guards и защитных тестов при изменениях файловых операций, хранения, доступа и приватности. При высоком системном риске или недостаточном покрытии quick использовать verify. Полный lint по риску, в том числе в quick для archive/privacy/storage, и обязательно на финальном qualify. Полный набор JVM, lint, ARM64, DEX и exact-source receipt обязательны перед выпуском; не удалять/ослаблять тесты ради скорости. Промежуточные CI разрешены без повторного согласования; при достаточной локальной проверке лишний CI не нужен. С 24.11.2026 по решению владельца рабочий цикл 1.7.227 включает до двух последовательных незавершённых этапов; текущий этап 1 уже технически завершён, ближайшая пара — этапы 2–3, затем 4–5, затем 6 отдельно. Отчёт/Сводка после каждого, следующий только после завершения предыдущего; обязательное согласование новых макетов и проверки по риску неизменны. Активный запуск не отменять и HEAD не менять.
Режимы quick (быстрая обратная связь), verify (полная JVM + lint, без APK), qualify (JVM + lint + ARM64 + DEX + exact-source receipt), perf (отдельный бенчмарк). Все CI-метки взаимоисключающие. Не запускать повторно активный CI; опрос примерно каждые 60 секунд до терминального статуса в пределах активного сеанса. Не использовать эмулятор. Не считать статический CI заменой проверки на реальном устройстве.

scripts/run-jvm-ci.py — единственный штатный полный runner: один bulk + один граф Gradle с отдельной Test-задачей и JVM на каждый изолированный метод. Не восстанавливать старый runner, режим audit, удалённые YAML и архив из Git-истории. docs/ci/allowed-workflows.json — разрешённые семь workflow; изменения только после явной сверки назначения. Пять исследовательских workflow не являются альтернативой сборке; инструмент подписи выдаёт только инструменты без секретов.

Сохранить актуальный обязательный inventory docs/ci/required-jvm-tests.json (2552 ID на 1.7.227 Stage 1, 2551 PASS и 1 ранее согласованный Shazam skip на VERIFY #45466830628); новые/удалённые идентификаторы требуют осмысленной сверки. Не ослаблять тесты, не скрывать ошибки и не повторять функциональные сбои ради зелёного статуса. Семантический аудит необходимости каждого теста отложен отдельно по решению пользователя.

Перед подписанием проверять успешное завершение exact-SHA qualification, live HEAD, все хеши и DEX; повторить DEX на окончательном подписанном APK. GAPI и ключи подписи вне GitHub. Выдача только Google Drive, ARM64, точные исходники отдельным архивом, без Releases/prereleases. Реальная проверка Xiaomi обязательна прежде стабильного выпуска. Не восстанавливать старые сборочные маршруты из других веток. Сводка.md и Правила.md должны ссылаться на этот регламент.
