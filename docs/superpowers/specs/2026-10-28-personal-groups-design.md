# Личное и действия с группами — согласованное ТЗ

1. Добавление публичного завершённого файла в настроенное «Личное» не требует PIN/биометрии и не открывает приватные данные. Пользователь остаётся в текущем разделе. Если защиты ещё нет, сначала выбирается способ входа; после настройки перенос завершается и интерфейс возвращается обратно. Чтение/просмотр, возврат, удаление приватных файлов и смена защиты требуют входа.
2. При открытии «Личного» с биометрией системный запрос появляется автоматически, без «Подтвердить вход». PIN показывает поле сразу, NONE открывается сразу. Отмена не вызывает повторных запросов; остаётся «Повторить вход». Автозапрос только при RESUMED, без цикла при уходе в фон или отмене; ручная блокировка не должна сразу сама запускать разблокировку.
3. На шапке группы в списке отдельная кнопка ⋮, доступная и при свёрнутой группе. Меню: в избранное (если все уже избранные — убрать), добавить в папку, переместить в личное, удалить (красные текст и иконка, подтверждение с количеством). Действие охватывает все записи группы в текущем разделе, включая нераскрытые «Показать ещё». Неполные/неуспешные операции показывают счётчики успехов и ошибок; отмена корутины не маскируется.
4. Папки и «Личное» сохраняют groupId/исходную связь: список — группы с общим меню, сетка — отдельные миниатюры (четыре в ряд). В каждом разделе/папке группа содержит только присутствующие там записи. Приватный раздел получает свой запоминаемый список/сетку. Возврат/удаление личной группы доступны после входа; удаление приватных файлов навсегда с отдельным предупреждением.
5. Обычное групповое удаление переносит в корзину; приватное удаление навсегда. Групповые избранное/папка меняют только каталожные назначения, не раскрывая приватных файлов в обычных списках. Нельзя обойти вход через повторный move(id) для уже приватной записи.

Реализация использует существующие безопасные операции копия→DB→публичная очистка, без повторного извлечения метаданных/изменения groupId. В активных группах файловые действия применимы лишь к завершённым файлам; недоступные задачи не должны незаметно считаться успешными.
