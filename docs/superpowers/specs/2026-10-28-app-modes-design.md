# Downloader, Gallery and Music modes

Approved conversation design: title switches Downloader / Gallery / Music; remember last mode. Existing Downloader remains. Gallery is a dedicated photo/video grid with viewing, edits, folders, favorites and protected Personal entry. Music provides tracks and persistent playlists; queue follows selected list, supports existing background playback/repeat/shuffle/editors. Source selector in each new mode independently remembers App files / Phone files, defaults to App. Phone files are browsed in place with on-demand permissions, edits produce new output, deletion requires confirmation. Personal stays separate/protected. Removing a playlist or membership never deletes audio bytes. Playlist track ordering is editable.

Implementation choices (builder decisions): reuse existing viewer/editor/service on content URIs; phone rows remain ephemeral metadata in ViewModel, never imported into download history on viewing; MediaStore supplies photo/video/music metadata on IO. Phone albums use MediaStore bucket names. Existing app folder/favorite actions remain via DownloadRow; Phone files support viewing/edit/share/delete and album browsing. Public playlists accept app and phone track IDs without copying. Unavailable/permission-revoked playlist tracks remain recorded and are reported, never silently removed. Existing Personal entry is available in both modes, but phone files are not implicitly imported into it. No new encryption/security contract.

Main screen contains mode title and source selector. Gallery offers all/favorites/folder filters and app folder creation. Music offers tracks/playlists, create/rename/delete playlists, add/remove tracks and move up/down ordering. New modes use home + settings bottom navigation; Downloader keeps three existing destinations. Settings shared. Last mode/source persistent. No new app name, icon, version bump or release unless requested separately.

Android permissions: SDK33+ READ_MEDIA_IMAGES/VIDEO or AUDIO; SDK34 partial selected images is supported; legacy READ_EXTERNAL_STORAGE (max32). Request only upon Phone source selection; denial offers retry/settings. Resume refresh reflects permission revocation and external file changes. Never load bitmaps for whole library. Internal Personal storage cannot enter MediaStore queries. Device deletion uses OS request on30+, recoverable permission29, direct delete with legacy write permission28; app confirmation first. Failure is visible and retains entry.

## Shared interfaces
Package data.library:
- enum AppMode { DOWNLOADER,GALLERY,MUSIC }, enum LibrarySource { APP,PHONE }
- class PhoneMediaLibrary(context:Context): suspend fun scan(mode:AppMode):List<DownloadEntity>; companion fun permissions(mode:AppMode,sdk:Int=Build.VERSION.SDK_INT):Array<String>. Stable IDs phone:<type>:<MediaStoreID>, providerId device. AppMode.GALLERY returns photos/videos, MUSIC returns audio. Permission denial/revocation never returns stale private metadata; check each granted collection. groupId is bucket display name for images/video. Metadata only, no imports/writes.
- data class MediaPlaylist(val id:String,val name:String,val trackIds:List<String>)
- class PlaylistRepository(context:Context) { val playlists:StateFlow<List<MediaPlaylist>>; suspend fun create(name:String):String; suspend fun rename(id:String,name:String); suspend fun delete(id:String); suspend fun addTracks(id:String,trackIds:List<String>); suspend fun removeTrack(id:String,trackId:String); suspend fun moveTrack(id:String,trackId:String,delta:Int) }. Persist JSON in dedicated preferences, atomic mutation, deduplicate IDs, retain unavailable IDs, reorder clamp bounds, no physical I/O to media.

Root owns preferences, permission/deletion launchers, phone ViewModel StateFlows, navigation/viewer queue snapshot. Gallery/Music screens consume props and callbacks only; no direct media deletion or permission requests. Root provides composable title/source controls so screen files stay independent.
