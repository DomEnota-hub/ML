# ML 1.7.171 / code231 — MP4 на этапе BACKUP_VERIFIED

## Подтверждённая причина

На предоставленном пользователем Instagram_24_1.mp4 (28512478 байт) воспроизведён отказ строгого сравнения после FFmpeg remux: длительность аудио 73.118231 → 73.118005 с, duration_ts 3224514 → 3224504 при time_base 1/44100. Разница — 10 отсчётов / около 0.23 мс. Все PTS/DTS совпадают, отличается только duration последнего аудиопакета. Сжатые потоки и декодированный звук совпадают по SHA-256. Видео не изменилось. Исходный файл на Google Drive и его скачанная копия не изменялись; производные файлы создавались только в /tmp.

## Исправление без ослабления контроля

Если обычный remux не сохраняет точную сигнатуру MP4, используется запасной механизм Mp4HeaderDates. В приватную копию исходника переносятся все байты; меняются только creation/modification поля ISO BMFF mvhd/tkhd/mdhd. Размер файла, таймкоды, edit lists, длительности, таблицы и медиаданные остаются прежними. Структура разбирается с проверками границ, версий 0/1, расширенных размеров и однозначности заголовков. Повреждённые/неизвестные заголовки отклоняются до записи копии.

Проверяются все записанные даты, неизменность расположения полей и SHA-256 каждого байта вне этих полей. Дополнительно сохраняются прежние строгие проверки FFprobe-сигнатуры и SHA-256 сжатых потоков. Числовые допуски для аудио или длительности не увеличивались. Дополнительные теги даты, способные переопределить заголовки, запрещают запасной путь при неоднозначности. Основной ранее успешный remux остаётся для файлов, проходящих точную проверку.

## Адресная проверка

- Четыре JUnit-теста PASS, скомпилированы штатным Kotlin 2.0.21 вне Android Gradle: версии 0/1 и обычные/расширенные блоки; побайтное равенство вне полей дат; повреждённый медиабайт; обрезанные/дублированные/неизвестные заголовки; запрет исходник=копия и неверной даты. Это экономит повторную компиляцию debug приложения.
- Выполнен код Mp4HeaderDates из приложения на пользовательском MP4, искусственном фрагментированном MP4 и обычном тестовом MP4. Для всех совпали точные сигнатуры потоков/длительности/таймкоды и SHA-256 сжатых потоков; FFprobe подтвердил новую creation_time. Исходные SHA-256 остались прежними. Содержимое реального видео и его копии в репозиторий не добавляются.
- Остальные модули и полный цикл проверок не запускались. Код журнала/MediaStore/перепривязки версии 1.7.170 не изменён; его 20 адресных проверок повторно не запускались.

## Продолжение

Журнал v1 сохранён. На BACKUP_VERIFIED результат неудачной проверки ещё не получил newHash/contentVerified: обычное «Продолжить по журналу» заново подготовит копию с новым запасным механизмом. Уже завершённые замены сохраняются, очередь не начинается заново. Установить APK поверх текущего приложения без очистки данных, затем нажать «Продолжить по журналу».

Подтверждение индексации даты в прошивке телефона остаётся необходимым. При неоднозначной структуре/дополнительных датах/реальном несовпадении потоков операция по-прежнему останавливается с оригиналом и резервом.
