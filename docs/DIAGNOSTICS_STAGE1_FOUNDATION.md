# MediaLoader — расширенная диагностика, этап 1/7

Основа: `release/1.7.6-youtube-status` (версия 1.7.6, code 68).
Рабочая ветка: `feature/1.7.7-diagnostics-stage1`.

## Что реализовано

Строго отделённый от UI набор Kotlin-доменов в
`app/src/main/java/com/domenota/medialoader/core/diagnostics/`:

1. **DiagnosticContracts.kt** — стабильные непрозрачные коды проверок, подсистемы,
   строго ограниченные категории достоверности `NONE / OBSERVED / HISTORICAL / VERIFIED`,
   состояние, область (локальная/сетевая), обязательность, срок годности,
   дата/длительность, безопасный код причины и ссылки на события.
2. **DiagnosticAssessment.kt** — детерминированное вычисление статуса подсистемы и
   приложения с учётом неизвестных и устаревших результатов. Необязательные
   компоненты (например LaMa) не создают глобальную красную ошибку.
3. **DiagnosticCoordinator.kt** — однократный исполняющий цикл над будущими
   read-only адаптерами: отмена, лимит времени, сериализация и изоляция
   исключений. Без подтверждения пользователя сетевая проверка не запускается.
4. **DiagnosticRunStore** — контракт будущего постоянного хранилища результатов,
   без конкретной записи на диск до отдельного этапа.

### Инварианты

- `OK` и `ERROR` требуют `VERIFIED` — реального выполнения проверки.
- Сохранённая сессия, наличие файла LaMa, прежняя успешная загрузка не являются
  доказательством текущей исправности.
- Отсутствие результата или истечение срока его актуальности не приводит к `OK`.
- Исключение/таймаут диагностической проверки = `UNAVAILABLE`, а не
  неисправность проверяемого компонента.
- Отмена `DiagnosticCoordinator` никогда не вызывает методы очереди загрузок.
- Поле `reasonCode` принимает только код, не URL, cookies, stack trace, имя файла
  или произвольный `Exception.message`.
- В локальном режиме сетевые адаптеры **не вызываются**.
- Режим `WITH_NETWORK` требует явного `networkConsent=true`; интерфейс и само
  получение согласия будут реализованы позднее.

### Граница этапа

Пока **не реализованы**:
- проверка Instagram/YouTube/VK/RUTUBE и музыкальных источников;
- запросы к yt-dlp / FFmpeg, очереди, хранилищу, LaMa;
- UI нового экрана, журнал неисправностей и экспорт;
- сохранение истории на диск и запуск проверок по расписанию.

Для этого предназначены этапы 2–7 исходного ТЗ
`MediaLoader_1.7.6_Расширенная_диагностика_ТЗ.md`. Никаких
диагностических запросов, пробных скачиваний, обновлений или пользовательских
изменений этот коммит не инициирует.

## Проверки этапа 1

- Пустые и неполные результаты не становятся зелёными.
- Устаревшее доказательство теряет силу; изменение часов учитывается.
- Ошибка необязательной модели красная в собственном разделе, но только
  предупреждение в общем статусе.
- Идентификаторы события / причины не допускают URL с токенами.
- В локальном режиме сетевая проверка не выполняется.
- Сеть требует подтверждения; таймаут/исключение не становятся ложным ERROR.
- Две параллельные проверки не стартуют одновременно.
- Отмена освобождает блокировку и не отменяет загрузки.

После CI предоставить пользователю отчёт и **дождаться его подтверждения**, прежде
чем добавлять реальные локальные проверки этапа 2.
