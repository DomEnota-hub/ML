# Журнал 1.7.17 и диагностическое обновление 1.7.18

## Наблюдения

- На телефоне запустилась 1.7.17 (79). В 14:46 выполнены два сканирования VK; оба завершились за 0,4–0,5 с с `kind=OTHER`.
- Журнал 1.7.17 не содержит метода и числового кода VK API. Поэтому причину ответа `OTHER` по нему определить нельзя.
- Пользователь сообщил, что скопированная ссылка имела домен `vk.ru`. Валидатор 1.7.17 принимал только `vk.com`, так что эту ссылку он отклонял до сетевого запроса. После ручной замены домена обе задачи запускались, но заканчивались `OTHER`.
- Массовые HTTP 403 миниатюр Instagram относятся к предыдущему сеансу 1.7.16 (78), до запуска 1.7.17. В журнале 1.7.17 нет данных для оценки миниатюр.

## Изменения в 1.7.18 (80)

- Валидатор принимает `vk.ru`, `www.vk.ru` и `m.vk.ru` с прежней проверкой точного домена.
- При ответе VK сохраняются только метод API и числовой код API или HTTP. Ключ, тело ответа и адрес сообщества в журнал ошибки не записываются.
- Неизвестный код VK показан в сообщении задачи. Это диагностическое обновление; причина второго сбоя выяснится после следующего реального запроса с сервисным ключом.

## Проверка на телефоне

Установить 1.7.18 поверх 1.7.17, вставить исходную ссылку `https://vk.ru/schrodinger_humor`, запустить поиск и экспортировать новый журнал. Если поиск снова закончится ошибкой, строка `VK job failed` должна содержать `method` и `api_code` или `http_status`.
