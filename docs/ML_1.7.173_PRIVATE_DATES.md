# 1.7.173 / code233 — возврат из личного с исходной датой

Обычный возврат фото/видео в стандартную папку MediaLoader сохраняет существующую дату съёмки/создания из метаданных. Когда такой даты нет, используется createdAtEpochMillis прежней записи истории (время постановки загрузки в очередь). JPEG/WebP под .jpg и MP4 обрабатываются кодеком восстановления 1.7.172 без перекодирования с потерями. Исходный приватный файл при подготовке не изменяется.

Публичная копия после публикации получает mtime исходной загрузки, затем сканируется. Проверяются размер, SHA-256 после повторного открытия и DATE_TAKEN MediaStore. Только после успешной публикации PrivateMediaOperations сохраняет новый URI в прежней записи и удаляет приватную копию. Ошибка проверки удаляет созданную публичную копию; приватный оригинал остаётся. Существующий ID/группы/поля истории сохраняются.

Старые приватные файлы используют прежнюю сохранённую дату истории. Временная датированная копия удаляется в finally. Для произвольной SAF-папки, Android ниже 10 и других форматов остаётся прежний возврат; сохранение положения в системной галерее там не гарантируется. Дата добавления новой записи MediaStore остаётся системной, поэтому итог зависит от используемой галереей сортировки. Проверка на одном фото/видео телефона необходима.

Проверки ограничены PrivateMediaOperationsTest и ARM64 assembleRelease с обязательным lintVital. Остальные модули и массовая миграция не запускаются. Основная подпись, версия/ABI и конфигурация проверяются перед доставкой. Draft PR без merge и GitHub Releases.

Результат: девять PrivateMediaOperationsTest PASS (включая новый тест актуального размера при прежних ID/дате; Kotlin 2.0.21/JUnit напрямую после начального Gradle-прогона восьми тестов). Итоговая assembleRelease SUCCESS и lintVital пройдены. Для Android ниже 12 используется совместимое чтение даты AndroidX, для новых — платформенный API. В историю записывается фактический размер опубликованной копии, поскольку добавление дат может изменить размер JPEG/WebP/MP4.
