# MediaLoader 1.7.7 (69) ARM64 — этап 8/8: интеграция и приёмка

**Ветка:** `release/1.7.7-diagnostics-integration-arm64`  
**Основа:** PR #43, успешная CI-сборка этапа 7 (`247eeb83b9d313a00f04a47d3849e5ea2fc025ec`).
**Базовое приложение:** 1.7.6 (68); новое: 1.7.7 (69); пакет `com.domenota.medialoader`; единственная ABI `arm64-v8a`.

## Интегрированный состав

Этапы 1–7 наследуются как последовательная цепочка коммитов:

1. Контракты достоверной диагностики и консервативные статусы.
2. Безопасные локальные проверки yt-dlp, FFmpeg, QuickJS, очереди, foreground-службы, папок, LaMa.
3. Состояние шести источников: локальная сессия, история и сетевой запрос только с явным согласием.
4. Структурированный локальный журнал неисправностей.
5. Исправление технического журнала: HTTP 403 активного музыкального поиска фиксируется отдельной ERROR-записью; кнопки управления всегда доступны, очистка подтверждается.
6. Полноэкранный экран проверки и журнал неисправностей.
7. Безопасный Markdown-экспорт через системный Android-документный интерфейс.

Этап 8 устанавливает версию **1.7.7 (69)**. Дополнительно исправлена регрессия: отменённая либо неудачная проверка больше не оставляет на экране незавершённые частичные результаты. Вместо них показывается последний целиком завершённый прогон либо состояние «Не проверено». Есть отдельные JVM-тесты восстановления.

## Автоматизированная приёмка

Финальный GitHub Actions на HEAD **этой ветки**:

- WebView / HitMoz / Muzmo JS-регрессия;
- Kotlin `testDebugUnitTest`, включая диагностику, конфиденциальность отчёта, отказ от ложных зелёных статусов, отмену;
- `lintDebug`;
- `assembleRelease`, без ключа подписи в CI;
- проверка через aapt: package/versionCode/versionName и ровно `arm64-v8a`.

После успешного CI: скачать артефакт строго соответствующего коммита, проверить SHA-256, выровнять zipalign, подписать исходным DomEnota-ключом, проверить APK v2/v3 и сравнить сертификат с ранее подписанной APK, повторно сверить package/version/ABI, выложить в Google Drive → «Загрузчик». **Ключ и пароль никогда не публиковать в GitHub**.

## Что обязательно проверить вручную на Android

### Экран и навигация
- Настройки → Диагностика → назад; отсутствие пустого экрана, лишней нижней панели и потери состояния других вкладок.
- Тёмная/светлая темы, длинные тексты, узкий экран, альбомная ориентация.
- «Проверить без интернета» и «Проверить всё»; явное согласие, отмена запроса, повторный запуск. Никакой сети от простого открытия экрана.
- Невозможность считать сохранённую сессию или HTTP 200 успешным скачиванием.
- Отмена во время проверки и повторное открытие: частичные результаты не объявляются подтверждёнными.

### Отказы и история
- Источник с HTTP 403, в том числе с неподходящим VPN: ошибка конкретной операции в техническом фильтре «Ошибки», но не ложный диагноз «сломался загрузчик».
- Работа кнопок «Обновить», «Очистить», «Закрыть», «Сохранить .md» в техническом журнале даже при большом количестве строк.
- Журнал неисправностей: повтор, требование перепроверки, устранение, подтверждаемая очистка независимо от технического журнала.
- Отсутствие LaMa не ломает статус остальных модулей; проверка SHA-256 модели не меняет её содержимое.

### Экспорт
- Сохранение безопасного `.md` через Android picker, отмена, смена имени, недоступная папка/нет места, корректная ошибка.
- Секреты, cookies, пути к медиа, ссылки и технические данные не должны попадать в безопасный отчёт.
- После отменённой диагностики выгружается лишь последний **завершённый** результат.

### Загрузка медиа, редактор, совместимость
- Проходы Instagram/YouTube/VK/RUTUBE и двух музыкальных источников, в том числе после смены VPN.
- Очередь и массовая загрузка; загрузка при сворачивании; корзина и восстановление.
- LaMa: выделение маски, удаление текста, локальная модель, отмена, контроль UI.
- Обновление **поверх** предыдущего подписанного релиза: приложение должно запускаться, настройки/файлы оставаться без потери.

**Автоматическая компиляция и подпись не доказывают правильную работу на телефоне.** Без результатов ручной проверки нельзя считать полную пользовательскую приёмку завершённой.

## Принцип завершения

До подтверждения пользователем выпуск сохранять как кандидат на приёмку, не сливать черновые PR в основную ветку и не выдавать неподтверждённый runtime как успешно проверенный.
