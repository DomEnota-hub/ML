# MediaLoader — расширенная диагностика, этап 2/8

**База:** этап 1 из PR #35, MediaLoader 1.7.6 (68).
**Рабочая ветка:** `feature/1.7.7-diagnostics-stage2-local-checks`.

## Архитектура и результаты

Добавлены консервативные **локальные** адаптеры к `DiagnosticCoordinator`:

| Проверка | Достоверно устанавливает | Чего НЕ устанавливает |
| --- | --- | --- |
| `runtime.ytdlp.library` | Присутствие Java-класса yt-dlp в APK | Версию, исправность исполняемого Python/yt-dlp, возможность скачивания |
| `runtime.ffmpeg.library` | Присутствие Java-класса FFmpeg | Запуск бинарника или успешность перекодирования |
| `runtime.quickjs.bundle` | Наличие `libqjs.so` в каталоге нативных библиотек APK | Готовность JavaScript-проверок |
| `queue.snapshot` | Чтение БД истории, количества статусов | Реальность сетевого прогресса и отсутствие зависаний |
| `queue.service_manifest` | Наличие регистрации foreground-службы в установленном APK | Запуск этой службы и её работу на фоне |
| `queue.foreground` | Факт успешного вызова `startForeground` в текущем процессе либо отсутствие активных заданий | Состояние ОС за пределами процесса / устойчивость в фоне |
| `storage.selected_folder` | Наличие сохранённого разрешения SAF, метаданных, признаков чтения/записи | Успешность реальной записи (нет тестового файла) |
| `storage.free_space` | Свободное место во **внутреннем хранилище приложения** | Запись в выбранную пользователем папку/внешний том |
| `editor.lama.sha256` | Наличие и контрольная сумма модели относительно pin `LaMaModelStore.SHA256` | Возможность ONNX-инференса |
| `editor.onnx.library` | Наличие класса ONNX Runtime | Успешность инициализации и обработки |

Заведомо неполная проверка возвращает WARNING/UNAVAILABLE вместо ложного OK.
Отсутствующая необязательная LaMa сама по себе не считается поломкой всего MediaLoader.

### Механика

- Новые изолированные файлы: `core/diagnostics/LocalDiagnosticRules.kt` (чистые решения,
  JVM-тестируемые) и `data/diagnostics/LocalDiagnosticProbes.kt` (Android-адаптеры,
  создаются фабрикой, но **не запускаются до подключения UI на следующих этапах**).
- В существующем `ActiveDownloadService` только две точки наблюдения:
  после `startForeground` и в `onDestroy`.
  Не меняются жизненный цикл, уведомления, постановка в очередь, отмена,
  автоматическое восстановление и foreground-политика.
- Полноценная целостность LaMa вычисляется с потоковым SHA-256 на Dispatchers.IO
  с проверкой отмены и ограничением времени 120 с.
  Не создаются ONNX-сессии и не загружаются модель/файлы.
- Метаданные SAF читаются без создания файлов и без запросов новых разрешений.
- В очереди читается `repository.downloads.first()`, без модификаций БД.
  Нет надёжных отметок последнего прогресса в текущей БД: «зависание» не
  подтверждается и не придумывается.
- Классы yt-dlp/FFmpeg ищутся без инициализации (`Class.forName(..., false, ...)`).
  Техническую готовность runtime нельзя проверить безопасно без дальнейшей
  отдельной реализации; отображать «библиотека есть, запуск не проверен».

### Границы этапа

**НЕ реализованы**: сетевые пробы, реальная проверка сессий сервисов, тестовые
скачивания, тестовая запись файла, обновление yt-dlp, установка LaMa, работа
ONNX-модели, UI, журнал неисправностей и постоянное хранилище результатов.
Сохраняется `versionName=1.7.6` / `versionCode=68`. Отдельный APK
не нужен: нужна компиляция в CI, unit tests и Android lint.

## Дополнительный этап журнала (требование пользователя)

Зафиксирован GitHub Issue #37: при `MuzmoWebView` `mainFrame=true`
ответ 403 был записан как DEBUG и не попадал в фильтр «Ошибки»;
кнопки «Обновить / Очистить» скрыты из-за компоновки окна. 
**Новый отдельный этап после исходного этапа 4** должен согласовать
классификацию итогового сбоя операции с техническими событиями (403 не
равен поломке приложения), исправить диалог, добавить регрессионные проверки.
План теперь **восемь этапов**, нумерацию последующих этапов уточнить при приёмке.
В рамках этапа 2 исходный журнал и поиск музыки не менять.

## Условия приёмки

- Все read-only адаптеры собираются в Android без запуска/записи.
- JUnit: запрет ложных зелёных статусов, контроль дефектов LaMa,
  обработка отозванных разрешений SAF, безопасная foreground-классификация,
  неизменность истории загрузок.
- GitHub Actions: tests, lint, ARM64 assemble, без слияния PR.
- После CI: отчёт, пауза перед началом следующего этапа.
