## Goal and product boundaries
Map existing plain lyrics to actual sung audio, without changing the original words, modifying source audio, uploading audio/lyrics, or fabricating timestamps. Prefer verified synced lyrics already available. Keep plain original if evidence is insufficient. First pilot on admitted public tracks, single track only, explicit command. No batch/automatic start until accuracy and resource budget confirmed. Generated result is an alternative version, not a replacement for authoritative LRC; save in internal version-bound cache only, include model revision, algorithm version, lyrics digest and audio source version. Reject stale result, changed track/text, cancellation and privacy revocation using current admission and DuplicatePrivacyGuard. Do not create UI/TaskCenter jobs that claim progress without a real executor.

## Candidate comparison
- Russian wav2vec2: https://huggingface.co/LooNuH/loom-wav2vec2-ru-onnx (claims Apache-2.0; ONNX int8 ~355 MB, export for lyrics alignment on vocal recordings). Upstream https://huggingface.co/jonatasgrosman/wav2vec2-large-xlsr-53-russian . Also https://huggingface.co/onnx-community/wav2vec2-large-xlsr-53-russian-ONNX . Confirm model revision, exact weights/quantization, license and tokenizer before use.
- GigaAM-v3 CTC (not punctuation/normalizing e2e model): https://huggingface.co/ai-sage/GigaAM-v3 (MIT, 220–240M, Russian speech with background music in training domains; not evidence of singing alignment). GigaAM-v2 int8 Android-oriented reference https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-ctc/nemo/russian.html . Older v1 weights have NC restriction; do not confuse versions.
- T-one: https://github.com/voicekit-team/T-one (Apache-2.0 code and weights, 71M, Russian telephony speech; compact baseline, unknown singing quality). Android ONNX reference https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-ctc/t-one-ctc-models.html .
- Singing-specific ceiling: https://huggingface.co/mrfakename/w2v-bert-2.0-music-lyrics-ctc (full-mix CTC, Cyrillic vocabulary, 600M class; actual Russian coverage, training rights, ONNX and device budget unverified). Investigate only; do not ship based solely on declared model license.
- MMS forced alignment: https://huggingface.co/Project42/mms-300m-align (CC BY-NC 4.0) and https://github.com/MahmoudAshraf97/ctc-forced-aligner (Russian romanization reference). Research only; not a default distributable model.
- ASR fallback comparison: https://github.com/ggml-org/whisper.cpp Android tiny/base; map recognized timestamps to original words, never substitute words. https://github.com/ijuinryukichi/lyric-align for an alternative reference. No assumption of reliable singing recognition.
- Optional vocal separation only if full-mix benchmark fails; compare against identical audio and measure resource cost. No new runtime or separation weights selected yet.

## Research milestones
1. Pin permissive model revisions, file hashes, licenses (code/weights/training restrictions separately), vocabulary, preprocessing, sample rate and frame-to-audio time mapping. Use existing ORT Android 1.20.0 if supported, no extra runtime without evidence. Download as optional AI model after model-manager compatibility checks; do not include weights in APK or commit them to ML. ML-models distribution only after license verification.
2. Offline benchmark: at least 15–20 consented/licensed songs covering Russian clear vocal, dense accompaniment, fast vocal/rap, long melisma, repeated chorus, pauses, live/remix and incorrect text. Include English and mixed language as secondary coverage. Use held-out line onset references from genuine timed lyrics verified against recording; negative pairs and instrumental control. GTSinger Russian annotated singing may be used only within its CC BY-NC-SA 4.0 research conditions (https://huggingface.co/datasets/GTSinger/GTSinger/blob/main/dataset_license.md), not a bundled corpus; full music mix separate. Do not send user media to external services. No test songs/lyrics in repository unless redistribution permitted.
3. Compare CTC Viterbi/forward-backward evidence on exact text, then ASR timestamp anchors if necessary. For each song, report coverage of original nonempty lines, median/p90 onset absolute error among accepted lines, within 0.5s/1s, wrong accepted lines, missing/ambiguous lines and wrong-track rejection, full-song time, peak RAM. Do not average away failed tracks; report by song and genre. Pilot acceptance targets (proposal, not established facts): >=90% accepted line coverage on eligible clean tracks, median <=0.5s, p90 <=1s; reject wrong/instrumental pairs and unsupported language; calibrate confidence on independent examples. No uniform interpolation. Repeated chorus and mismatched versions must not yield silently shifted timelines.
4. Android pilot: bounded chunks with overlap, preserve absolute time and correct boundary reconciliation, cancel/revoke gates, resource coordination with OCR/waveform/music playback and editors. Measure Xiaomi RAM, runtime, temperature/battery, playback responsiveness and interruption/restart. Benchmark weights before selection; no promises of speed. UI only if quality gate passes: single automatic sync action in existing lyric settings, actual progress/cancel and plain fallback, preview then save alternative to internal cache. No manual editing or new directory. Existing player uses TrackLyrics/LyricLine, local cache and positionMs; do not alter working synced LRC. Partial low-confidence results require a representation that does not accidentally highlight/seek unaligned lines; until verified, decline whole generated result.
