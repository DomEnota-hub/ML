# MediaLoader 1.7.224 · этап 3 · идентичности папок, счётчики и строки

Дата: 24.11.2026 (МСК). PR #189, ветка `feature/ml-17224-inapp-folder-picker`.
База: 1.7.223, SHA `23291b25177a02c7f136781afa677946e846dd73`.

## Причины и изменения

- В визуальных MediaStore bucket без подтверждённого `relative_path` поле `groupId` могло отображаться как **путь**, хотя это лишь название/подсказка альбома. Теперь такие группы имеют явный статус «Расположение не определено»; имена совпадающих независимых bucket различаются порядковыми суффиксами. Ключи сканирования не меняются; неподтверждённый путь не создаёт иерархию.
- `DuplicateFolderPathResolver.apply` принимает только пути для bucket с корректным namespace volume и безопасными сегментами. Нельзя подставить путь для посторонней группы, смешать разные provider keys или нарисовать ложного родителя.
- Счётчик выбранных **физических папок** объединяет только одинаковые подтверждённые directoryId; оригинальные ключи сканирования остаются отдельно и фильтрация по-прежнему точная. Количество файлов берётся из уникальных допустимых URI. Отсутствующий, отрицательный или переполненный размер не становится фиктивным числом.
- «Вложенных папок» теперь считает реальные дочерние узлы, включая промежуточные и исключая собственный узел.
- Строка дерева разделена на название (до 2 строк), проверенное расположение/явный неизвестный статус и постоянную строку «файлы, дочерние папки, размер». Длинный путь больше не вытесняет счётчик. Footer использует безопасные сводные показатели.
- Исправлены пропущенные Compose `Modifier`/layout импорты в тесте предыдущего этапа, ранее не скомпилированном в CI.

## Регрессии и ограничения

Добавлены 7 новых обязательных тестов (реестр 2474 → 2481), сохранены старые ID и прежний разрешённый skip. Проверяют неподтверждённые bucket, совпадающие имена, отсутствие расширения области, проверенный общий путь, размеры null/отрицательные/overflow, число дочерних папок, неверный namespace и длинные названия.

**Статус:** изменения и тесты подготовлены, но JVM/lint/Gradle и физическая QA Xiaomi ещё не выполнялись; зелёный CI не заявляется. Проверка реальных Android 16 MediaStore и размещения на экране обязательна.

**Далее:** этап 4 (полные регрессии и UI, включая ранее известные ошибки), один `qualify` на frozen SHA после завершения пакета; выпуск ARM64 только после успешного CI и офлайн DomEnota-подписи.
