# ML 1.7.206 / 266 — блок 1 из 4: инвентаризация и остановка старого HIDE/SHOW

Статус документа: реализация первого согласования. Аппаратное тестирование на Xiaomi Android 16 не проводилось.
Исходная контрольная точка: 1.7.205, `feature/ml-17205-hidden-v2`, `30e505d31e706f26ce0cd43b2f301bb88dc3f85d`.
Новая ветка: `feature/ml-17206-visibility-nomedia`, основана непосредственно на указанном SHA.

## Граница работы и карта зависимостей

| Слой | Фактические точки | Решение в блоке 1 |
| --- | --- | --- |
| Compose / запуск | `ui/MediaLoaderApp.kt`: `toggleFolderVisibility`, `visibilityOperation`, выбор альбома, вызовы `startFromVisibleActivity` и `resumeFromVisibleActivity` | Скрыть старые переключатели, блокировать до запроса MANAGE_EXTERNAL_STORAGE; старый pending-диалог только для чтения |
| Foreground / команды | `FolderVisibilityWorkCoordinator.kt`, `FolderVisibilityService.kt`, in-memory `VisibilityWorkCommandSlot` | Не принимать старые новые/повторные запросы; не отдавать брони service; защита и при обходе UI |
| Транспорт | `FolderVisibilityManager.kt` -> `FolderVisibilityBatch`, `FolderVisibilityMove`, `AndroidFolderVisibilityPorts` | Запретить `preview`, `setHidden`, физическую смену membership и `resume` до любого копирования, delete, write journal или background gate |
| Состояние и доказательства | `CatalogVisibilityState`, `FolderVisibilityReadPolicy`, `FolderVisibilityLibraryGuard`, `ExternalMediaCatalogRepository` | **Сохранить** исходные receipts, excluded/retired-алиасы, app bindings и защиту доступа к старым физически скрытым файлам |
| История скачанного | `HistoryDatabase.downloads`, `HistoryRepository`, `catalog_assignments` | Без миграций/перезаписей; ID, даты, URI и привязки сохранены |
| Личное | `PrivateFileStore`, `PrivateMediaOperations`, `PrivateAccessManager` | Не менять; его собственный перенос, SHA и приватная изоляция **не являются** HIDE/SHOW обычных папок |
| Фоновая медиатека | `HistoricalRecoverySignals`, `LibraryViewModel`, `PhoneMediaLibrary` | Ни одной новой операции HIDE/SHOW. Сохранять защитные проверки старых незавершённых состояний; исключать их безопасно после нового модульного каталога в блоке 2 |
| Следующий механизм | Пока отсутствует | В блоке 2: отдельный реестр SAF/DocumentFile + `.nomedia`, локальный фильтр ML, сохранение history/URI |

**Почему исходники транспорта не удалены побайтово:** `FolderVisibilityReadPolicy` и существующие receipts читают их типы для скрытого архивного состояния; преждевременное удаление типовых зависимостей может открыть скрытые файлы или обнулить жизненно важную диагностику. В блоке 1 активный транспорт именно отключён во всех точках входа. Зависимые read-only определения будут разделены при вводе новой модели в блоке 2.

## Унаследованные состояния: только диагностика

| Обнаружение | Безопасное поведение |
| --- | --- |
| `batch.bin` / `move.bin` (v1) | Не переписывать, не мигрировать, не перезапускать |
| `checkpoint-v2.bin` (v2) | Не записывать, не стирать, не создавать новую версию |
| Незавершённый `SHOW 0/4`, `FV_DESTINATION_STATE`, `ALLOCATED` | Не объявлять возврат выполненным; оставить исходные пути и контрольную точку |
| Неудачный `HIDE 0/8` / `PLAN_SIZE_MISMATCH` | Не выдумывать успешный перенос; read-only проверка и отчёт об отказе |
| Повреждённый/двойной/неизвестный журнал | Fail-closed; отсутствие нового переноса, данные сохраняются |
| Старый owner-marker, `.nomedia`, исходные и скрытые файлы | Ничего автоматически не удалять |
| Отсутствие доступа к старым скрытым файлам | Не выдавать записи за доступные; не открывать через подменные URI |

## Структура четырёх согласований

1. **Блок 1 (исходные этапы 1–2):** аудит, блокировка старых переносов во всех публичных и внутренних точках, сохранение read-only старых журналов, независимая проверка и отчёт. После блока — явное подтверждение владельца.
2. **Блок 2 (этапы 3–4):** реестр видимости, `.nomedia`/SAF, независимый фильтр ML, сохранение Room-истории и правильная доступность URI; проверка 1/8/46. Следующее подтверждение.
3. **Блок 3 (этапы 5–7):** исправление мигания галереи и memory pressure, кэш «Часто слушаю», удаление неошибочной красной подписи, полный текст ошибок. Следующее подтверждение.
4. **Блок 4 (этапы 8–9):** полный JVM/Compose/lint/ARM64, одна подписанная DomEnota QA 1.7.206, исходники и проверенная доставка `Загрузчик/1.7.206`. Затем владелец отдельно подтверждает аппаратную QA Xiaomi. Не объявлять stable до реальных результатов.

## Предварительные критерии завершения блока 1

- Старые видимые кнопки и разрешение «доступ ко всем файлам» не запускают физический HIDE/SHOW.
- Прямые API `preview`, `setHidden`, `changeMember`, `resume` и foreground reservation блокируются **до** операции.
- Журналы и доказательства старого хранения в текущей версии не чистятся и не меняются.
- Весь уже существующий функционал «Личное», история, разрешённые медиа и провайдеры не изменены.
- Автоматические тесты подтверждены на точном SHA после компиляции; при CI-падении нельзя заявлять завершение.

**Оставшееся:** старая физическая модель хранится в read-only зависимостях и не должна быть переиспользована новым модулем. При недоказанном состоянии legacy journal строгий privacy guard пока может блокировать часть медиатеки. Снятие этого условия без безопасной адресной политики запрещено; это предмет блоков 2–3. Реальная Xiaomi Gallery не тестировалась.
