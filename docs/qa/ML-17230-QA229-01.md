# QA229-01 — native controller leak during Gallery swipe

Base: f3a92e8fe22e56e08b7016d278cb2983176b3dde, 1.7.229 (289). Scope: one defect, 1.7.230 (290).
Evidence: six visible occurrences in the 7.451 s recording. The foreign strip contains a separate bottom bar, time labels and overflow chevron; the current GalleryVideoChrome instead puts labels around one Canvas track. Media3 1.9.0 PlayerView creates a PlayerControlView from exo_controller_placeholder, setPlayer calls maybeShowController, and setUseController(false) initiates controller.hide() before animation was disabled in the previous factory. This explains the transient native bottom controls. The application must never create that native hierarchy in Gallery, not merely hide it.
Implementation: a Gallery-only PlayerView XML with no controller placeholder or controller, use_controller and auto_show disabled at inflation. The Media3 1.9.0 content layout retains its video surface container, shutter, image/artwork, subtitles, buffering, error and overlay layers. Native-only methods and coordinate listeners stay exclusively in standalone mode, animation disabled before attachment there. Recomposition uses separate layout identity. No change to pager policy, privacy, media data, Compose timeline geometry, or standalone controller resources.
Regression: existing GalleryVideoChromeTest extended with actual view inflation, repeated construction and native hierarchy/required surface assertions. Mandatory inventory +1 (2568 total). CI not yet verified. Physical Xiaomi acceptance: rapid swipes both directions and video/photo/video, paused and resumed, seek, lock, rotation, both navigation modes; no foreign controller at any intermediate frame. Do not claim device PASS from JVM. Prior performance finding not included.
