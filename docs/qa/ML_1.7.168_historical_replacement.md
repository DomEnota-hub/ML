# MediaLoader 1.7.168 / code228 — восстановление исторических дат

Продолжение Issue #113 на основе рабочих новых JPEG/MP4 записей из проб 1.7.162/163. Работает с завершёнными публичными JPEG/MP4 из Pictures/MediaLoader. Историческая дата — createdAtEpochMillis из истории ML (время постановки загрузки в очередь, не доказанное время завершения).

## Два режима одной сборки

В Настройках → Лаборатория медиатеки → Восстановление медиатеки находятся соседние синий и янтарный блоки.

1. «Проверить на одном файле»: выбрать имя/дату, подтвердить одну реальную замену. После успеха открыть этот файл из «Загрузки» в режиме «Загрузчик» и проверить его дату/положение в системной галерее.
2. «Массовое восстановление»: становится доступным по сохранённой успешной пробе. Запускается только вручную, обрабатывает файлы последовательно. Новая версия после пробы не требуется.

При ошибке очередь останавливается. «Продолжить по журналу» возобновляет сохранённый этап. Пока публичная замена ещё не началась, можно отменить оставшуюся очередь, сохранив уже завершённые результаты. Переход к следующему файлу после ошибки автоматически не выполняется.

## Имена и удаление

Проверенный приватный резерв и датированная staging-копия создаются до изменения публичного оригинала. Оригинал получает уникальное служебное имя; новая app-owned MediaStore запись в прежней папке создаётся с точным исходным именем, сначала pending. URI фиксируется в журнале до записи байтов. Android не должен молча переименовать копию; конфликт имени останавливает операцию.

Исторические EXIF/MP4 даты и mtime устанавливаются до публикации, затем проверяются DATE_TAKEN, размер/хеш, доступность и связи. Старый публичный файл удаляется только после всех этих шагов и фиксации DELETE_INTENT. Сбой после удаления разрешается по точному старому URI и журналу, не по похожему имени.

Приватные проверенные резервные копии остаются в данных приложения. Они не видны в галерее и занимают дополнительное место примерно по сумме обработанных исходников. Их автоматической очистки и отката уже удалённых публичных оригиналов в этой версии нет. До удаления оригинала ошибки сохраняют имеющиеся оригиналы/резервы; для незавершённой операции предусмотрено продолжение, а не автоматическое переписывание истории назад.

## Идентичность помимо URI

| Привязка | Поведение |
| --- | --- |
| DownloadEntity.id | Остаётся прежним; новая история не создаётся |
| originalName / папка | Сохраняются; размер обновляется после изменения метаданных |
| source/group/bulk/derived/recognition | Сохраняются полным сравнением снимка строки |
| Избранное и папка ML | Остаются на прежнем downloadId |
| MediaStore ID / phone ID | Новый физический ID связывается со старым через алиасы |
| URI / media / file / file-stat алиасы | Старые и новые адреса объединяются с устойчивым ID |
| Внешний каталог и плейлисты | CAS документов с сохранением ключей, состава, порядка и неизвестных полей |
| Локальные превью в истории | Ссылки на прежний URI переводятся на новую копию отдельным шагом |
| VK images / hashes | URI переводятся на новую копию; исходный SHA остаётся алиасом для повторного скачивания, новый SHA добавляется отдельно. PK публикаций сохраняются, конфликт чужого хеша останавливает замену |
| Позиция и просмотр видео | VideoWatchProgress сохраняет существующий устойчивый ключ и связывает физические алиасы |
| Кеши галереи и миниатюры | Сканирование приостановлено на время операции, затем кеш/идентичности обновляются; URI-кеши пересоздаются под новым адресом |

Активные загрузки и задания сообществ VK препятствуют запуску. На время замены блокируются обычные файловые мутации, редактирование каталогов и запуск воспроизведения; плееры освобождают старые URI. Воспроизведение останавливается, текущая аудиоочередь очищается. Новые фоновые запросы не должны вмешиваться в замену. Внешние приложения не подчиняются внутреннему lock; изменение исходного файла/строки обнаруживается повторными проверками и останавливает обработку.

## Проверки и границы доказательств

Локально выполняются только HistoricalReferenceLinksTest и RecoveryHistoryCasTest: CAS истории, альбом/избранное, телефонные ключи, плейлист/позиция, повторное выполнение, конфликт каталога, URI+SHA VK. Общие тесты UI/редактора/AI и полный lint не запускаются; assembleRelease выполняет обязательный lintVital.

JPEG проверяется по неизменённому JPEG-потоку вне EXIF, метаданным и декодированным полосам; неподдерживаемые EXIF структуры отклоняются. MP4 remux без перекодирования сопоставляет свойства/потоки/rotation/HDR side data и SHA сжатых потоков. Нативная FFmpeg-задача завершается до освобождения gate при отмене.

Здесь не подключено Android-устройство. Реальные пользовательские файлы на сервере не обрабатывались. Проверка результата в галерее Xiaomi и открытие из «Загрузок» выполняются пользователем сначала на одном выбранном файле. Успешные host-тесты не объявляются проверкой OEM галереи или реального сбоя питания. Массовая обработка никогда не стартует при установке/открытии приложения.
