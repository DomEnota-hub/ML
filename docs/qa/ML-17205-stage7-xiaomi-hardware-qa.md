# MediaLoader 1.7.205 — этап 7: протокол аппаратной QA (Xiaomi Android 16)

**Статус:** инструкция/подготовка, **не отчёт о прохождении**. Не объявлять физические испытания выполненными до журналов и подтверждения владельца.

## Перед обновлением
1. Убедиться, что подписанный QA-артефакт имеет пакет `com.domenota.medialoader`, versionCode 265, ARM64 и оригинальный сертификат DomEnota SHA256 `4f6f0ddf4d8fd2669fd2a3a6ebab6e84bda17281a3a5badada0e1eeb73a4f1d2`. Проверить контрольную сумму APK по актуальному README. Не устанавливать неподписанный технический APK.
2. Установить **поверх** имеющейся 1.7.204: не удалять приложение, не очищать данные, noBackup журналы, скрытые файлы, `.nomedia`, owner marker, Private или историю.
3. Если обнаружен прежний `SHOW 0/4` с checkpoint `ALLOCATED` и `FV_DESTINATION_STATE`, **вначале только read-only инвентаризация**. Не продолжать этот перенос без независимой резервной копии исходных тестовых элементов и сверки точных URI, размера и SHA. Не создавать новую операцию при неизвестном/конфликтном состоянии журнала.

## Сценарии после безопасной read-only проверки
- Для **только неценных тестовых копий**: пакеты по 1/8/46 файлов, фото/аудио/видео, одинаковые имена из разных исходных папок, крупный файл, чужой владелец MediaStore и штатный/отклонённый Android permission.
- **HIDE**: предохранительная копия, проверка preflight, неизменённый исходный SHA, скрытая папка и `.nomedia`, отсутствие файла в ML и системной галерее; подтверждённые чекпойнты и отсутствие дубликатов.
- **SHOW**: файл возвращён в первоначальное размещение с идентичными байтами SHA-256, доступен в ML и системной галерее; проверены даты, ссылки/история и отсутствие лишних публичных копий.
- **Отказ до мутации:** `PLAN_FAILED_NO_MUTATION` не изменяет байты, не создаёт durable batch и не запускает обязательный глобальный перескан Галереи/Музыки.
- **Прерывания:** Home, переход между Галереей/Музыкой/плеером, приостановка, возобновление, перезапуск процесса на каждой из пяти фаз, только на тестовых копиях и при наличии бэкапа. Отказ от разрешения/нехватка места/изменённый источник должны fail-closed: без удаления неподтверждённого оригинала, с сохранением журнала.
- **Стабильность UI:** строка прогресса только в «Загрузчике», X/Y не сбрасывается на 0/0 при подтверждённом успехе; не мигают Галерея, Музыка, обложки и количество файлов; миниплеер остаётся функциональным. Сохранить запись экрана и журналы расширенной диагностики.
- **Muzmo:** повторить загрузку MP3 `МУККА — Вселенная`, проверив, что сервер `rmr.muzmo.cc` направляет на `ds2.mzmdl.com`; допустим только точный HTTPS + `/get/music/YYYYMMDD/*.mp3`. Сохранить редактированные логи `MP3 request/redirect/response`; успешный результат только после проверки фактических MP3-байтов. Не ослаблять защиту для произвольных адресов, не пересылать cookie.
- **Результат:** отдельно отметить кодовую техническую QA и реальный аппаратный результат, время полного переноса p50/p95 на сравнимых наборах, какие сценарии PASS/FAIL/NOT_RUN, наличие остаточных старых журналов. До реального PASS не делать merge, production, Release или prerelease.
