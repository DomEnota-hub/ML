# QA05 и QA17: жизненный цикл и главная

База: fce413709eba17997c7ae730cda38e39a498c415 (247). Исходный QA05 MP4 просмотрен локально: пять кадров за2.25с показывают пустые коллекции, работающий мини-плеер и позднее появление полосы под заголовком. Статичные данные не доказывают ни повтор MediaStore scan, ни зависимость от playback ticks.

## Подтверждено по фактическим путям

- `LibraryViewModel.completedDownloads` уже применяет distinct после отбора завершённых публичных строк; скачиваемые байты не запускают переиндексацию. `index` зависит от appReferences/gallery/music/privateKeys/recovery. Позиции плеера среди входов нет.
- `BackgroundLibraryProjection` строит результат на Default с identity keys. Root Compose подписан на audio state, поэтому position tick может вызвать recomposition, но не меняет эти keys. Регрессия проверяет20 recomposition с готовой пустой выборкой и ровно одним построением.
- `ready` ранее одновременно означал свежесть и возможность отображения. При сохранённом безопасном результате он становится false на время нового расчёта; коллекции/«На разбор» безусловно показывали полосу. Теперь `usable` отдельно означает наличие результата для текущей приватности; `ready` по-прежнему блокирует мутации до актуализации. Смена privacy немедленно скрывает старый результат. Первоначальная загрузка и явные операции сохраняют прогресс.
- Коллекции и обложки сохраняют предыдущие данные на время пересчёта; source refs и privacy остаются авторитетными. Room collection/review emissions deduplicated структурно до UI.
- Batch preview имел отдельную доказанную причину скачка: пересоздание условного Image при изменении полного spec. См. batch-editor report. Геометрия теперь постоянна, quality не меняет render key.
- MusicMode/SmartMusic вычисления keyed candidates/interval/preferences/revision, а не позицией проигрывания. Очереди keyed сохранёнными sessions/candidates; дубликаты запускаются явной операцией service с отменой; thumbnail decoding по URI/kind/revision/size; разрешения и MediaStore observers остаются включены. Gallery album/group projections продолжают зависеть от библиотеки и фильтров, не от тиков.

## Измерения

Добавлен ограниченный набор атомарных счётчиков `LibraryWorkCounters`: COMPOSITION, MEDIASTORE_SCAN, MEDIASTORE_QUERY, THUMBNAIL_DECODE, BACKGROUND_PROJECTION, LIBRARY_INDEX_BUILD, COLLECTION_EMISSION, REVIEW_EMISSION. Последние два — именно emissions, а не SQL query count; EXPLAIN/Room SQL profiler здесь не запускался. Фиксированные ключи, никаких URI/имён/миниатюр. Накопительный snapshot `Perf/LIBRARY_WORK` при уходе приложения в фон позволяет сравнить разницу до/после выбранного сценария. Это диагностическая возможность, не готовые показатели улучшения.

Подключённого устройства нет (`adb devices -l` пуст), `/dev/kvm` отсутствует. Достоверные baseline/after для телефона, фактические recomposition/SQL/decoder timings и влияние фонового воспроизведения не получены. Нельзя считать отсутствие полосы доказательством устранения повторных сканов. Нужна ручная запись counters/Perf на одной библиотеке при:30с playback без изменений; переключении Галерея/Музыка; возвращении из фона; одной новой загрузке; отзыве доступа/переносе в Личное. Неизменные данные не должны давать новые scan/decode; изменение должно дать необходимое обновление; при ошибке сохраняется прежнее разрешённое содержимое.

## QA17

`ui/home_organization_visible` по умолчанию false: только главная Загрузчика передаёт `organizationContent=null`, поэтому HomeScreen не добавляет его Spacer. Сохраняются DAO, маршруты, данные, запись новых Inbox entries и коллекции Галереи. Подписки коллекций ограничены активной Галереей/маршрутом коллекций/явно включённой главной; Inbox — маршрутом review/включённой главной. Флаг обратим локально, после смены нужен перезапуск. Unit policy и Compose тест проверяют скрытие/возврат. Пользовательское управление новым флагом не добавлено: это локальный переключатель выпуска.
