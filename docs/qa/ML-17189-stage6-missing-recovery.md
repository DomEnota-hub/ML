# ML 1.7.189 stage 6 — QA-188-07 missing-file recovery

Diagnosis: the legacy matcher required exactly one returned candidate even though a single Instagram Reel commonly yields a root video and an extracted audio choice. The deferred buffer persisted only URLs; its open/retry-all route and login callbacks discarded the recovery ID. These are concrete code defects, not a captured trace of the actual phone request.

- Use the same ordinary resolver, title policy and transfer engines. A legacy single Instagram visual can match despite derived audio, but a partial/multiple carousel or an unverified audio alternative must remain ambiguous. Exact recorded keys and provider/format/publication verification are preferred. No title/size/position guessing and no arbitrary replacement. Legacy extracted audio is accepted only with a verified original video locator. Other legacy providers require a unique matching format and publication.
- Durable v2 deferred entries distinguish ordinary new downloads and each recovery history ID, including the same URL. Legacy URL-only entries migrate as ordinary. Manual open, retry all, login, direct retry and process restart retain explicit recovery intent; remove only the completed target. Already-present eligible rows do not download again. Cancellation and failures retain unfinished entries. Corrupt v2 storage is never reinterpreted as ordinary links.
- Recovery-specific preview/confirmation; no rename dialog, alternate download, music search or saved-frame action. Cancel does not overwrite the old row. Identity failure and provider failure are separately labelled.
- Opt-in coroutine publication context: existing download engine stages the file, verifies media type and nonzero content, computes SHA-256, persists exact new output URI before write, verifies published checksum/length, atomically rebinds the old row. Serialize public restore with private/history mutations. Preserve existing row ID/date/metadata/catalog/favorite/collections, no review inbox entry or second history row. Completed referenced output is never deleted; on interruption an unreferenced output is cleaned only if still fingerprint-confirmed or app-owned pending MediaStore row. Unverifiable partial or changed files block retry; the original row survives. A corrupt journal fails closed. Legacy Android uses an exclusive file locator and scanner notification. Original catalog folder is preserved; actual physical publication uses current storage settings, not guessed missing path. No fabricated DATE_ADDED. Public recovery rejects private/hidden/inaccessible targets; no private file is exported.
- Physical final APK acceptance: reported Reel DfJq2fdoCdM, direct/after login/deferred/restart, multiple recovery targets and one ordinary link, failed provider vs ambiguous match, carousel and legacy, original returns, cancellation/retry/parallel target, checksum and interrupted publication, original sort/metadata/favorite/collection/catalog, no new review item, actual file bytes/MIME and public permissions. Test on disposable copies; no claim of live service or real Android MediaStore/SAF verification from JVM. Tiny process-death gap between provider allocation and journal record and OS pending cleanup remains a platform boundary; no automatic deletion of arbitrary/changed files.

No interim APK, merge, release or signing. QA-188-16 and previous-track rule remain stage 7.
