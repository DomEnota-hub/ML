Session writes are idempotent, position-only changes do not bump stats/rank; first credit bumps rank, elapsed playback bumps stats. Transactional per-track UTC-minute totals backfilled from existing buckets; inserts/updates/deletes update only changed minutes. Day detail remains session-level; aggregate uses exact original timestamps for legacy portions. Full recomputation is still required for changed projection inputs; raw session credit/history is authoritative.
- Explicit JSON projections in the listening DB, maximum 32 entries, 1 MiB each. Keys include complete eligible identity digest, periods, calendar/timezone, mix settings and session membership/occurrence IDs. Revision-checked writes, current privacy/exclusion/clear invalidation; no cached result authorizes playback. For a rolling rank, exact expiration and future-credit boundaries. Calendar/timezone/clock system broadcasts and a cancellable one-shot deadline replace a permanent Compose polling loop. No initial speculative zero; one rank for overview/detail. Incomplete catalog never replaces a confirmed audio generation. Mix seed persists; stats recalculation only when needed. Current catalog/permission check precedes cold disk display, so it is not unconditional instant restore.
- Independent complete audio catalog and stable audio-only current history. Exact typed app-audio locator alias cache with MediaStore version/generation, current Room row, full audio access, privacy epoch, bounded atomic write. No untyped locator or old unknown generation is reused. Existing phone catalog and full fallback remain; no universal delta scanner.

## Work reduction
- Large (>128) browse/search/sort/folders/playlist projections computed on a background worker; explicit filters and access guard prevent cross-filter/privacy display. Small libraries use direct path. Stable list/index references, playlist counts/order, no repeated linear lookup per row. Public session rows assembled in worker. Recent and folder lists are lazy. Excluded folders still support explicit playback.
- Resume resolution builds key/track indices once per membership generation, scalar checkpoint updates reuse mapping; actual queue capture only on timeline, relevant metadata, explicit access or visibility change. Library audio preview reuses timeline queue. Private guard scans changed timeline/access, checks current item otherwise. Full order, occurrences, shuffle/repeat/speed retained. Queue checkpoints still persist atomically on IO. No truncation of Media3 legacy queue or change to its external controller behavior.
- Exact selected ID/URI in audio open, O(n) map instead of per-row linear search; selected file gets fresh presence/identity checks. Larger analytics queues reuse current validated catalog and short-lived presence cache, with live permission/privacy/URI recheck. Derived cache is not authorization. Date label formatting bounded, locale/timezone-sensitive. New fixed diagnostic counters distinguish queries, cache hits and queue captures.

- Existing waveform disk reuse, atomic writes and per-key independence retained; RAM LRU bounded to 128 arrays (up to 1 MiB of float payload), lock records retained only by active/waiting callers. Eviction never deletes valid disk waveforms. Disk read/publication and invalidation serialized per key. Existing duplicate fingerprint/cache/journal and recognition URI+content journal remain unchanged and are covered by existing regressions.
