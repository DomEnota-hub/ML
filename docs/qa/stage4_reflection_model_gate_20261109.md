## Определения и ограничения

- **Удалить отражение** = отделить отражённую сцену на оконном/витринном стекле от сцены *за стеклом*. Не путать с SRNet «Убрать блики» (локальный зеркальный блик на предмете), удалением объекта LaMa или цветовой коррекцией.
- Нельзя гарантировать восстановление полностью скрытого за непрозрачным отражением содержимого; зеркала как основной объект съёмки не поддерживаются; должны быть отдельные отрицательные примеры без стекла.
- **Неподтверждённая модель не делает режим рабочим**. В коде `AiEraserMode.REFLECTION.available == false` до проверки легальных весов, локального ONNX/Android ARM64 inference и качества.
- Запрещены изменения production, собственные GitHub Release/prerelease/APK, Dropbox и публикация весов сторонних моделей. Исследовательский CI скачивает веса ВРЕМЕННО и уничтожает их после выполнения, не публикуя артефакты.
- Аппаратная Xiaomi QA, включая видимые артефакты/тепловую деградацию/память, выполняется пользователем ПОСЛЕ единого QA-выпуска. Предварительная проверка на Linux CPU не заменяет тест локальной Android модели.

## Gate качества и безопасности

1. Веса доступны на конкретном URL, известны точные SHA-256, размер, разрешённый статус **и кода, и весов**, нет секретов.
2. Запускается ПОДЛИННЫЙ pretrained inference через ONNX Runtime CPU на нескольких разнообразных композициях отражения, а не identity, Photoshop blur или LaMa.
3. Есть paired tests: ground-truth чистой сцены, отражённый слой, смешение, сравнение PSNR/SSIM (до/после), негативный тест чистой сцены; сохранить метрики и failure cases.
4. Измерить FPS/CPU и peak RSS на Linux; для ARM64 проверить доступность ONNX операторов/хранилище/потоковые настройки. Не использовать GPU/TensorRT-цифры как прогноз Xiaomi.
5. Only after 1–4 passed: скачать модель по явному действию пользователя в AI Models, SHA, cancel/delete, optional mode; отдельная истинная ONNX обработка; preview/undo/compare/save с восстановлением полноразмерного оригинала при нулевых изменениях.
6. Green unit/lint/assembleRelease ARM64, full model smoke, версия QA и доставка **двумя архивами только на Google Drive**; тогда создать отдельный `STAGE_04_DONE`. На устройстве = `DEVICE_QA_PENDING`.

## Реальный исследовательский запуск PINTO ONNX (2026-11-09)

- CI: https://github.com/DomEnota-hub/ML/actions/runs/42590331785
- Исходный ONNX скачан **временным образом** из публичного upstream Release, не копировался в наш репозиторий, не предоставлялся пользователю и не публиковался как APK.
- `dinov3_vits16_disthyper_residual_gennerator_640x640_320x320.onnx`: **89,242,337 байт**, SHA-256 `99b197b7579f2022a38d8570ed94d972037304e5e689c51ba774e03f1f884b48`.
- На Linux CPU ONNX Runtime 1.20.1 модель действительно выполнила реальный pretrained inference: input `[1,3,640,640]`, выходы `transmission` и `reflection`, оба `[1,3,320,320]`.
- CPU: 1,45 / 1,47 / 1,40 с на одном CI-хосте. Максимальная RSS: **1 085 048 KiB (~1,04 GiB)**. Нельзя переносить это время и память напрямую на Xiaomi.
- Отрицательный пример без отражения: выход отличается от исходника MAE 0,02569.
- Синтетическое смешение `0.85 * scene + 0.15 * reflection`: MAE до **0,05837**, после **0,09347**. Результат ХУЖЕ исходного смешения, PSNR снизился с 23,253 до 19,46 dB.
- При более сильном смешении `0.65 * scene + 0.35 * reflection`: MAE до **0,13620**, после **0,17644**; PSNR с 15,893 до 13,80 dB.
- **Итог: этот конкретный вариант НЕ ПРОШЁЛ gate качества; не активировать режим, не загружать модель на Android, не использовать как готовое решение.** Статус исследовательского CI `failure` ожидаем при негативном результате теста качества; нельзя просто убрать assert ради зелёного CI.
- Дополнительно Meta [DINOv3 License](https://github.com/facebookresearch/dinov3/blob/main/LICENSE.md) допускает распространение при соблюдении отдельных условий и передаче полного текста лицензии; MIT-лицензии репозитория PINTO недостаточно для юридического оформления производного файла без отдельной проверки.

Следующий исследовательский кандидат: Apache-2.0 DExNet и публичный checkpoint, который ещё необходимо реально получить, измерить и изучить. Никакой `STAGE_04_DONE` не создан.


## Проверка опубликованных весов DExNet (2026-11-09)

- Официальная ссылка автора: https://drive.google.com/file/d/1jkhCvyrQAQZtLaxdDWDkkSOF0NZ12aJp/view
- CI: https://github.com/DomEnota-hub/ML/actions/runs/42598622086, **completed/success**.
- Файл DExNet.pt: **118 442 981 байт**, SHA-256 `b58316c3cb339c0b334b83d5855446d19e5d57c49f88bc3b529b0da54498bcd3`.
- PyTorch `torch.load(weights_only=True)` прошёл безопасно. Найдены структуры `epoch`, `iterations`, `opt_g`, `weight`, 1867 тензоров, **9 656 424 обученных параметра** (36,8 MiB FP32); весь checkpoint содержит дополнительное состояние и не является готовой Android-моделью.
- Веса не опубликованы на GitHub и не загружались в рабочие или production-ресурсы приложения.
- Критическое ограничение: официальный eval использует `--hyper`; `models/DExNet_model_sirs.py` всегда включает `if_hypercolumn = True` и требует **VGG19 features** из `torchvision.models.vgg19(pretrained=True)` для добавления **1472 feature channels**. Сам файл DExNet.pt не доказывает наличие и права VGG19-весов, а память и стоимость ONNX (с VGG19) ещё не измерены.
- Исходный код опубликован с Apache-2.0; конкретные права на экспорт и коммерческое распространение checkpoint/VGG19 необходимо подтвердить отдельно.
- **Статус кандидата: доступ к весам подтверждён, качество/полный ONNX Android/юридические условия НЕ подтверждены. Не активировать отражения, не маркировать этап 4 DONE.**
