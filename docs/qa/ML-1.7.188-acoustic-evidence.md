# QA-187-06 local acoustic fingerprint evidence

Implementation: original pure Kotlin spectral peak-pair landmarks with 1024-sample Hann FFT at mono 8 kHz, 256 hop, broad frequency bands, relative time deltas and offset voting. Streaming Android MediaExtractor/MediaCodec decode supports PCM16/float output; downmix and box-filter downsample use constant memory. A 6,000-landmark deterministic reservoir retains features throughout the recording. Confirmation requires at least 90 distinct landmark hashes aligned within one frame and spanning at least six seconds. This detects matching fragments; it does not prove interchangeable complete tracks. Exact SHA-256 / encoded sample hashes remain distinct from acoustic fingerprints.

The inverted hash index ignores hashes appearing in more than 40 tracks and verifies only pairs sharing at least 90 hashes. These bounds deliberately allow false negatives in unusually repetitive libraries. Acoustic/possible groups require manual selection; bulk selection only selects N−1 exact-content copies. Every member must match every other member; weak chains cannot create a confirmed group. Existing uncached rehash of selected/retained files, current-track protection, provider-confirmed recoverable trash and last-copy guard are retained.

No new library, copied algorithm code, native binary, ABI, network permission, external service, music download or GAPI call is introduced. The implementation uses Kotlin/JDK math and the existing Android platform decoder, adding no third-party licensing obligation or JNI ABI burden. Supported codecs depend on the platform. ARM64 compilation/device decoder compatibility requires the coordinated Android build/device checks.

Memory/CPU: single sequential decoder at Android background thread priority, cancellation checked at codec polling, FFT windows, indexing, pair comparison and grouping. Decoder inputs/outputs are released on cancellation/error. Each track is capped at 6,000 landmarks; in-memory checkpoint LRU is 64 tracks. The whole library's fingerprints/index still scale with track count. Cache files are app-private/no-backup, URI/stable-row identity plus size/mtime checked, algorithm version in cache directory, stale/unavailable cache not trusted for deletion. Completed per-track checkpoints support resumed scans; atomic report replacement preserves the last success on cancellation. Audio/PCM never leaves the device or writes temporary PCM files. Public scan input excludes hidden/private rows. Before committing a move to Private, a repository-wired callback durably advances one privacy epoch, clears only duplicate checkpoints/reports and the in-memory LRU, invalidates background scan tokens and stops its service. Checkpoint/session persistence shares the revocation lock and rejects old track epochs, including delayed UI saves and restored old snapshots. The dialog immediately clears stale reports/previews; preview and trash verification also reject old epochs. Epoch state stores one integer, no private media identities. Temporary in-process blocked IDs and already-captured PublicMediaIdentity aliases cover the revoke-before-private-save interval, including fresh scans of stale catalog aliases; public restore admits a newly scanned row after the public DB save. If report/cache clearing fails, private DB commit is prevented and the newly imported private copy rolls back. Public duplicate results need a fresh scan after any private move.

Limits: this is host JVM evidence on short synthetic signals. It is not Android MediaCodec output validation, a benchmark of 700 typical full-length songs, worst-case 6,000-landmark/index memory, real-music accuracy calibration or Xiaomi playback-impact/cancellation/thermal evidence.
