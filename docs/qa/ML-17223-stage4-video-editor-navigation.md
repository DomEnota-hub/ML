## Кодовая причина, подтверждённая анализом

`MediaLoaderApp.kt`, ветка `LibraryRouteContent(VIDEO_EDITOR_ROUTE)`: если `accessibleDownloads` не содержит нужную запись даже на одном проходе композиции, раньше немедленно выполнялся `LaunchedEffect(downloadId) { navController.popBackStack() }`, кроме `phone:` ID в специфическом режиме `awaitingPhone`. Для обычных сохранённых ID, при временно неготовых фоновых публичных проекциях, это приводит к возврату на viewer без ошибки плеера. Кодовой путь подтверждён; полную причинность конкретных физических переходов проверяем в новой QA.

## Реализовано

- Новый чистый `VideoEditorRouteAdmissionPolicy`: `OPEN` только при текущей доступной проверенной видеозаписи; `WAIT` при временном отсутствии; `EXIT` при явном запрете приватности или после стабилизации каталога / ограниченного времени ожидания.
- Привязанный к уникальному nav-entry таймер: минимум 2,2 секунды без преждевременного `popBackStack`, до 35 секунд при продолжающейся перестройке. Появление записи отменяет ожидание. Время измеряется через задержки корутин, а не настенные часы.
- Пока источник не подтверждён, нет плеера/повторного открытия устаревшего URI, только нейтральный индикатор.
- Явно запрещённые private/visibility/archive ID выходят немедленно. Само открытие использует исключительно `accessibleDownloads` и тип VIDEO.
- Перед выполнением отложенного `popBackStack()` сверяется точный `NavBackStackEntry.id`, чтобы старый эффект не закрыл другой экран.
- Журнал `VideoEditorNav` пишет `EDITOR_ENTRY_AUTHORIZED` и `EDITOR_ENTRY_UNAVAILABLE` с анонимными булевыми статусами и длительностью. Не пишет URI/путь/имя приватного файла.
- Критически важные существующие Media3/ExoPlayer и экспортный граф не изменены без доказательства сбоя кодека.

## Аппаратная приёмка Xiaomi Android 16

1. 10–15 быстрых повторов «видеоплеер → редактор → назад» с одним и несколькими видео. Не должно быть спонтанного возврата через 0,1–1 с.
2. Повторить в процессе активного обновления MediaStore и после переноса **не участвующего в видео** файла в «Личное». При реконструкции публичного индекса редактор может показать ожидание, но не попадает в бесконечный цикл открытия/возврата.
3. При переносе именно редактируемого видео в «Личное», удалении, отозванном разрешении и архивировании не допускать воспроизведения/превью через старый URI.
4. Сравнить временную диаграмму `VideoEditorNav`, `Perf screen_enter`, `VideoPlayer PLAYER_CREATED/RELEASE`. При реальном codec/GL crash потребуются внешние logcat/tombstone, поскольку локальный журнал 1.7.222 такой причины не зафиксировал.
5. Проверить переключение клипов и отмену/выход, чтобы новая задержка не блокировала явный пользовательский Back.
6. Новый APK только после общего `qualify` финального SHA и оригинальной подписи вне GitHub, без Releases.
