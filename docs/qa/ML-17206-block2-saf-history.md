## Фактически реализованный целевой путь

- Ранее действовавшие физические HIDE/SHOW v1/v2 остаются выключенными, старые journals и скрытые физические файлы оставлены без replay, удаления и миграции.
- Точка выбора дерева через `ACTION_OPEN_DOCUMENT_TREE`/ActivityResult; приложение получает persistable read+write SAF только для явно выбранного физического каталога.
- Реестр `folder_nomedia_v1`, version 1, с именем виртуальной папки только через устойчивый folderId, сохранёнными разрешённым tree URI и `ownedDocumentId`, признаками ML-visible и состояния системного маркера. Ошибка чтения реестра означает неизвестное состояние и запрещает публичное отображение.
- `NomediaFolderEngine` до `DocumentsContract.createDocument` записывает durable `PENDING_HIDE`. Восстановление до `DocumentsContract.deleteDocument` записывает `PENDING_SHOW`. После process death нет auto-commit/replay: требуется отдельная явная `reconcile` read-only операция.
- Вся физическая мутация ограничена именно служебным документом `.nomedia`; запрещены copy/move/delete/rename файлов медиа, изменение ContentResolver MediaStore metadata, Room/downloads, original-name, даты или статуса корзины.
- Уже существующий `.nomedia` считается **чужим**, даже если совпадает по имени с ранее созданным ML. При показе папки чужой маркер не удаляется. Свой маркер удаляется только при совпадении сохранённого SAF document ID и нулевой длины.
- Два отдельных результата: скрыто в ML и наличие подтверждённого файла `.nomedia`. **Наличие файла не доказывает, что Xiaomi/системная Gallery уже исключила медиа из индекса**.
- Глобальный PUBLIC Gallery/Music/collections guard учитывает новое множество скрытых catalog folder IDs отдельно от legacy receipts. Старые retired/hidden URI/proof сохраняют прежнюю строгую защиту.
- Файлы в `Загрузках` хранятся в существующей Room `downloads`; устойчивые ID, providerId, originalName, savedUri, даты, favourite и catalog assignments не изменяются. В списке истории скрытой папки не нужно маскировать карточку как удалённую; доступность исходного MediaStore URI проверяется по отдельной кнопке `Проверить доступ`.
- Если после исключения из MediaStore старый `content://media` URI недействителен, проверка так и сообщает. Никакой записи ложного нового URI без доказанной физической идентичности.
- `Личное` (PrivateFileStore/PrivateMediaOperations), уведомления, источники Instagram/YouTube/VK/RUTUBE/Muzmo, редакторы не менялись.

## Защитные условия

1. Выбранный SAF-каталог относится к локальному `com.android.externalstorage.documents`. Cloud-провайдер не может выдавать себя за систему хранения Android. Нужны подтверждённые постоянные права на чтение+запись.
2. `.nomedia` действует на **всё содержимое физического каталога и его подпапок**, а не исключительно на файлы виртуальной папки ML; при смешанном физическом размещении требуется явное предупреждение.
3. Пустой созданный ML marker и чужой произвольный marker различаются. Восстановление не трогает внешний marker, даже если тот скрывает файлы после восстановления внутри ML.
4. Процесс может погибнуть после создания маркера, но до durable completion. В таком случае mark fail-closed и read-only reconciliation, без автоматического удаления или присвоения собственности.
5. Прежде чем удалить виртуальный альбом или переместить его членов, новое скрытие должно быть снято с проверкой доступа. Удаление альбома не должно автоматически повторять старый физический `SHOW`.
6. Прежние legacy receipt/journal состояния `SHOW 0/4`, `HIDE 0/8`, `PENDING`, повреждение или конфликт не «исправляются» новым механизмом, и не сбрасываются ради стабилизации галереи.
7. При потере SAF-разрешения код не должен придумывать успешное изменение либо подменять MediaStore ID. Нужно повторное системное разрешение на тот же каталог.

## Автотесты и приёмка

- Уровень `NomediaFolderEngine`: marker-only create/show; foreign nonempty marker 47 байт; no deletion of foreign; identity mismatch; revoked permission; failure after create; explicit recovery; 1/8/46 history identities retained unchanged, unknown registry fail-closed.
- Уровень `FolderVisibilityReadPolicy`: новый скрытый catalog folder не превращается в старый physical receipt, private/corrupt protection stays.
- Уровень `DownloadsScreen`: запись `downloads` отделена от видимости в Gallery, статус/кнопка проверки доступа без авто-перепривязки.
- Полные автоматические full JVM/Compose, Android lint, ARM64 exact-source; независимый Storage/Pictures/History/Private.
- Ручная проверка Xiaomi Android16 проводится только после **общего** QA-дистрибутива блока 4; системную индексацию и статус видимости Android не объявлять подтверждёнными по JVM.

**Открыто до фактической полной приёмки:** возможность безопасно читать каждый скрытый документ через SAF в ML и подтверждать его точную принадлежность конкретной истории; необходимость повторной выдачи разрешения; состояния медиа после переиндексации Xiaomi. Прежде чем признать блок 2 закрытым, соответствующие функции или честные ограничения должны быть проверены.
