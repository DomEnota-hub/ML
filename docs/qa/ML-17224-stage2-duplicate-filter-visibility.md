# MediaLoader 1.7.224 · этап 2 · фильтры по фактическим результатам

Дата: 23.11.2026 (МСК). Ветка: `feature/ml-17224-inapp-folder-picker`, Draft PR #189.
База: 1.7.223, SHA `23291b25177a02c7f136781afa677946e846dd73`.

## Воспроизведённая причина

В `MusicDuplicatesDialog.kt` все четыре `FilterChip` («Все», «Точные», «Акустика», «Версии») отрисовывались безусловно, даже когда `result == null`, поиск ещё не запускался и список `groups` пуст. Значения нулевых категорий создавали впечатление результатов, которых не было.

В Галерее фильтры уже были ограничены разделом готового отчёта, но все категории показывались даже после завершённого поиска без находок. После восстановления другого отчёта сохранённый фильтр мог сделать непустой набор визуально пустым.

## Что изменено в исходниках

- Общая чистая `DuplicateResultFilterPolicy`: подсчёт групп, проверка непустоты, построение списка доступных категорий в фиксированном порядке и безопасный fallback несуществующего выбранного фильтра на «Все».
- Музыка: отдельный `MusicDuplicateResultFilters`. **Нет групп — нет фильтров.** Есть группа — «Все» и только категории с количеством >0. Две строки при нескольких категориях без пустых/обрезанных кнопок. Обновлён подсчёт и фильтрация завершённых отчётов. При смене фильтра список прокручивается к началу.
- Музыка: во время активного поиска фильтры появляются только когда уже существуют предварительные группы. Фильтрация предварительного списка отдельная, не переносится в финальный отчёт и не выдаёт неполный поиск за завершённый. Число групп и объём точных копий относятся к отображаемому набору. Нет предварительных групп — только прогресс.
- Музыка: до первого запуска при состоянии IDLE добавлено пустое состояние «Поиск ещё не запускался» с пояснением. Для завершённого нулевого отчёта сохранено «Совпадений не найдено».
- Галерея: отдельный `VisualDuplicateResultFilters`. Показаны только виды совпадений с группами. При пустом завершённом отчёте вместо бессмысленных фильтров выводится «Совпадений не найдено», действие корзины скрыто.
- Галерея и Музыка: выбранная категория, исчезнувшая после изменения результатов, **не может скрыть все группы**; отображение переключается на доступные результаты без изменения исходного отчёта.

## Добавленные регрессионные тесты

5 тестов `DuplicateResultFilterPolicyTest` и по 3 Compose-теста `MusicDuplicateResultFiltersTest` и `VisualDuplicateResultFiltersTest` (всего **11**):
- до поиска нет панели фильтров;
- отображаются только категории с положительным счётчиком;
- порядок категорий и подсчёт сохраняются;
- исчезновение активной категории переключает представление на «Все»;
- повторное нажатие корректно выбирает категорию.

Добавлены в обязательный `docs/ci/required-jvm-tests.json` (2463 → 2474), один ранее разрешённый skip сохранён.

## Аппаратная QA, не выполнена

1. Сразу при открытии «Дубликаты треков»: не показывать «Все/Точные/Акустика/Версии» и нулевые значения. Доступны режим поиска, запуск и пустое состояние.
2. Во время быстрого/расширенного сканирования без находок: только прогресс, без фильтров. После первых предварительных групп: появляются только категории с находками, список действительно фильтруется; корзина недоступна до завершения.
3. Завершённый нулевой поиск в Музыке и Галерее: понятный текст, никаких фильтров. Переход к сохранённому отчёту с находками: показать доступные категории.
4. Фильтровать отдельную категорию, затем обновить отчёт, удалив все группы этой категории. Должны отображаться остальные группы, а не пустой экран.
5. Проверить сохранённый отчёт/неполный checkpoint, журнал, разрешённые приватные действия и работу с каталогом после переноса файлов.
6. Проверить маленькие экраны, крупные шрифты, трёхкнопочную навигацию Xiaomi Android16 вместе с изменениями этапа 1.
