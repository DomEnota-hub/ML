# MediaLoader — расширенная диагностика: этап 7/8

**База:** успешный CI этапа 6, PR #42, коммит `482743e6fb9a472b7f19b749410db2108d6850fb`.
**Ветка:** `feature/1.7.7-diagnostics-stage7-safe-report`.
**Основная версия:** 1.7.6 (68) пока не повышается. Тестовая финальная сборка — этап 8.

## Цель

Отдельный безопасный экспорт результатов диагностики в Markdown для самостоятельного
чтения, передачи разработчику или сохранения через системный документный интерфейс.
Экспорт **не равен** полному техническому AppLog, который содержит существенно
больше внутренних подробностей и имеет собственную кнопку «Сохранить .md».

## Реализация

### Экспорт и разрешения

В `Настройки → Диагностика → Журнал неисправностей` добавлена кнопка
**«Сохранить безопасный отчёт .md»**.

- Пользователь нажимает кнопку вручную, Android открывает системное окно
  `CreateDocument("text/plain")`, рекомендованное имя
  `MediaLoader_diagnostics_yyyyMMdd_HHmm.md`.
- Приложение пишет Markdown только в URI, возвращённый **явным выбором** пользователя.
- Нет запросов на широкие разрешения к хранилищу, нет автоматических фоновых
  отправок, HTTP-обращений, аналитики или загрузки в облако.
- Запись идёт на `Dispatchers.IO`, через ContentResolver.
- При отказе/ошибке поставщика документов показывается сообщение без
  исходного текста исключения. Если запись прервалась, выбранный
  документ **может остаться неполным**; успешным экспорт не объявляется.
- Пока выполняется диагностика, экспорт недоступен. Если предыдущий запуск
  был отменён, разрешено сохранить только **последний полностью завершённый**,
  а не промежуточные результаты.
- Для совместимости с файловыми менеджерами MIME `text/plain`,
  расширение файла `.md`.

### Защитная граница отчёта

`SafeDiagnosticReport` — чистая Kotlin-функция без Android/API/сети, и она
собирает Markdown исключительно из разрешённых полей:

- версия приложения (в ограниченном формате) и версия Android SDK;
- время отчёта и время последней полностью завершённой проверки, в UTC;
- общий статус по свежим проверкам, количества актуальных/устаревших результатов;
- названия подсистем и проверок через `DiagnosticLabels` без внутренних кодов,
  обезличенные статусы и тип подтверждающих данных;
- короткие **фиксированные** пояснения по разрешённым кодам причин,
  а не текст `DiagnosticFinding.explanation`, `recommendation`;
- счётчики состояний очереди/истории только после узкого извлечения
  десятичных чисел, без переноса исходного текста;
- список структурированных неисправностей с фиксированными пояснениями
  `FaultExplanations`, временем, статусом, числом повторов.

Никогда не экспортируются напрямую:
- cookies, токены, сессии, заголовки HTTP, тело запросов и ответы серверов;
- пользовательские ссылки/поисковые запросы, URI и пути файлов, названия
  скачанных медиа и фотографии;
- `operationId`, `eventIds`, внутренние идентификаторы проверок,
  файлы моделей, stack trace, `Exception.message`, сырой AppLog;
- полные имена/домены сайтов двух музыкальных движков; на экране и в
  отчёте только «Основной/Резервный музыкальный источник».

Статические названия платформ Instagram/YouTube/VK/RUTUBE остаются, потому
что это явные запрашиваемые проверки. Отчёт не объявляется полностью анонимным:
в нём всё равно есть версия приложения, Android SDK и симптомы неисправностей.
Перед пересылкой пользователь может просмотреть сохранённый документ.

### Достоверность и повреждённая история

- Сборка отчёта не выполняет повторных сетевых или локальных проверок.
- `UNCHECKED`, `UNAVAILABLE`, `WARNING`, `ERROR` и `OK`
  сохраняют смысл, определённый этапами 1–6.
- Просроченное `OK` показывается как **«Устарело — нужна повторная проверка»**,
  а не как действительная исправность.
- Сохранённый `HTTP 403` — отказ анонимного документа; не доказанная поломка.
- Если локальные данные/журнал неисправностей повреждены или недоступны,
  экспорт явно сообщает «прочитать не удалось» и **не утверждает**, что
  проверок/неисправностей не было.
- При отсутствии истории — «Не проверено», а не «Исправен».
- Сохранённые источники не переписываются, журнал не очищается.

### Изменённые файлы

- `core/diagnostics/SafeDiagnosticReport.kt`: генератор безопасного .md.
- `ui/screens/DiagnosticsScreen.kt`: безопасная кнопка и системный picker;
  отдельная ссылка на последний завершённый run и флаги чтения истории.
- `core/diagnostics/SafeDiagnosticReportTest.kt`: JVM-тесты конфиденциальности,
  состояний и жизненного цикла.

## Приёмка и безопасность

JVM-тесты покрывают:
- искусственно внедрённые секреты в тексты проб и ссылки на события;
  ничего не попадает в Markdown;
- версии, приватные URL, ID операций, имена файлов и raw-exception строку;
- разрешённые суммы и статистику без передачи исходного текста;
- отсутствие предварительной диагностики и отсутствие ложного зелёного статуса;
- устаревшие проверки и ранее отменённый/локальный сетевой режим;
- журнал ACTIVE/NEEDS_RECHECK/RESOLVED и недоступную историю;
- HTTP 403/VPN без заявления о дефекте MediaLoader.
