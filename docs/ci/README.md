# MediaLoader CI — единственный актуальный регламент

**Решение:** заменить старые маршруты штатной сборки единой exact-source системой. CI PR #174: два A/B аудита #44945855009/#44945854128 PASS, полная проверка #44947470186 PASS на `a446c491095e1586caf594a168c1aaf057fce697`; удаление старой инфраструктуры — следующий проверяемый коммит. Никакого нового APK на этапе CI. 1.7.211 забракован на устройстве; следующий выпуск только после исправления VerifyError.

## Режимы

| Режим | Что выполняется | APK |
|---|---|---|
| quick | исходные guards, CI helper tests, компиляция, базовые + выбранные тематические тесты, точные ID/XML, изолированные Compose методы, lint по риску | нет |
| verify | guards, полная JVM-регрессия и lint | нет |
| qualify | guards, full JVM, lint, ARM64, кандидат и exact-source qualification receipt | неподписанный внутренний кандидат |
| perf | полный opt-in бенчмарк БД | нет |

Маршрут: .github/workflows/ml-ci.yml. **Промежуточные коммиты, открытие и обновление PR не запускают CI/Gradle.** Только явный workflow_dispatch либо одна метка ci:verify, ci:qualify или ci:quick-<profile> (baseline/archive/privacy/navigation/library/playback/editors/download/storage/diagnostics). Метки взаимоисключающие. Quick через dispatch допускает объединение профилей (quick_profiles, через запятую) и quick_lint; через метку один профиль. Профиль всегда включает базовый набор, проверки доступа, точный inventory ID/XML, свежие JVM/Compose workers; неизвестный профиль/лишние или пропущенные ID/неожиданный skip/дублированные маркеры блокируют результат. Quick не даёт qualification receipt.

По решению владельца 24.11.2026 каждый этап требует компиляции изменённых компонентов и адресной регрессии изменённых и зависимых компонентов, обязательных guards и защитных тестов при изменениях файловых операций, хранения, доступа и приватности. При высоком системном риске или недостаточном покрытии quick использовать verify. Полный lint по риску, в том числе в quick для archive/privacy/storage, и обязательно на финальном qualify. Полный набор JVM, lint, ARM64, DEX и exact-source receipt обязательны перед выпуском; не удалять/ослаблять тесты ради скорости. Промежуточные CI разрешены без повторного согласования; при достаточной локальной проверке лишний CI не нужен. С 24.11.2026 по решению владельца рабочий цикл 1.7.227 включает до двух последовательных незавершённых этапов; текущий этап 1 уже технически завершён, ближайшая пара — этапы 2–3, затем 4–5, затем 6 отдельно. Отчёт/Сводка после каждого, следующий только после завершения предыдущего; обязательное согласование новых макетов и проверки по риску неизменны. Активный запуск не отменять и HEAD не менять.

Перед следующими изменениями убрать CI-метку и дождаться терминального состояния. Опрос около 60 секунд; не дублировать запуски. При manual dispatch выбрать точную ветку и mode (по умолчанию verify); квалификация проверяет live HEAD. Не запускать qualify для чистого CI-аудита. При недоступности dispatch использовать явную профильную метку через тот же workflow, а verify — по риску/покрытию. Для комбинированного набора без dispatch при недостаточном покрытии одного профиля использовать verify. Не восстанавливать альтернативные workflow.

## Тесты и доказательства

Full runner: scripts/run-jvm-ci.py full — один bulk и один граф из 37 независимых Test-задач (каждая одна JVM); всего 38 точных маркеров, 2 вызова Gradle. Изоляция не ослаблена. Актуальный inventory docs/ci/required-jvm-tests.json: 2552 точных ID, 2551 PASS/1 известный opt-in Shazam skip на VERIFY #45466830628; новые, пропущенные, дублированные, упавшие или неожиданно skipped тесты блокируют результат. Новые ID добавлять после проверки смысла. Не удалять тесты ради скорости: отдельный аудит полезности отложен. Raw XML и логи сохраняются; не использовать кэш результатов тестов, компиляционный кэш разрешён.

VERIFY #44947470186: exact SHA a446c491095e1586caf594a168c1aaf057fce697; JVM 280.655 s против 404.676 s прежнего полного набора (~30.6% в двух запусках), 38 actual Test markers, 2359/2358/1; lint 915.448 s, 0 errors, 103 warnings (33 Information). Не считать ускорением общее время CI: lint остаётся отдельным узким местом, кэши и состояния runner различаются. Оба artifacts проверены SHA256 и CRC. Детальные A/B и DEX evidence — соседние документы. Командное окружение: Java17, Gradle8.9 SHA pinned, AGP8.7.3/Kotlin2.0.21, SDK35, configuration cache off. Кэш lane/epoch/Gradle inputs/source; без GAPI/keystore. При доказанном transport failure до тестов максимум один видимый retry; никаких ретраев функциональных ошибок.

## Адресные профили quick

Состав задаётся scripts/ci/focused.py по классам из обязательного inventory. Старые 24 focused classes сохранены всегда; к ним добавлены базовые access/privacy/write guards. Профили объединяются без дублей. Выбор по затронутым компонентам и зависимостям, а не по лимиту количества тестов; owner-approved high-risk changes требуют достаточной проверки, при сомнении verify. Для изолированных Compose классов выбираются все текущие методы из inventory, выполняется существующий отдельный Test worker через scripts/run-jvm-ci.py. Общий bulk исключает все пять изолированных классов. XML и маркеры сверяются с точным планом; raw evidence сохраняется. Не считать quick полной регрессией.

Пример dispatch: mode=quick, quick_profiles=archive,privacy, quick_lint=true. Пример метки: ci:quick-archive (полный lint обязателен). Baseline не подходит для изменений Архива. Локальные guards и unit-тесты инфраструктуры выполняются при любом CI. Проверка самого quick требуется до его принятия как доказательства этапа. Кэш: при пустом lane разрешён fallback на успешный JVM cache с тем же epoch и хешем Gradle inputs; не кэшировать результаты тестов, не менять репозитории зависимостей, ключи и GAPI вне CI.

## Выпуск

Qualify требует success quick+jvm+lint+arm64 на одном SHA/run, проверку ARM64/package/version, DEX invoke register-word validation, exact source ZIP и хеши. Не подписывать UNQUALIFIED без успешного всего workflow, receipt и live HEAD сверки:
`python3 scripts/ci/gate.py consume /path/receipt/QUALIFIED.json /path/candidate`.
Receipt допускает прежний успешный attempt того же run/SHA; не другой run или stale/cancelled HEAD. Negative probes (compile/lint/test) только qualify, без qualification receipt; проверять именно ожидаемую диагностику. После локальной подписи DomEnota проверить v2/v3, сертификат, zipalign, ARM64, DEX и хеш финальных байтов. Ключи/GAPI не передавать в GitHub. Выдача только Drive; без GitHub Releases/prereleases. Эмулятор не применяется, физическая приёмка отдельно.
