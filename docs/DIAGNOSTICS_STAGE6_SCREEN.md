# MediaLoader — расширенная диагностика: этап 6/8 (UI)

**База:** CI-подтверждённый этап 5, PR #41, SHA `4bd8b016deed22c227df2ccc4fb42c16cebf37b5`.
**Ветка:** `feature/1.7.7-diagnostics-stage6-screen`.
**APK-параметры:** базовая версия 1.7.6 (68); на промежуточном этапе версия и подпись не изменяются.

## Экран

Новый маршрут `diagnostics` открывается из настроек вместо старого статического диалога.
Открывается полноэкранно, без нижней панели навигации и мини-плеера.

1. Шапка «Диагностика», безопасная кнопка назад.
2. Общий статус, дата последней проверки, количество свежих и устаревших результатов.
3. «Проверить всё» — сначала отдельное объяснение и согласие на запросы к шести сторонним серверам; «Только локально» запускает безопасный офлайн-режим. Отмена и закрытие не изменяют очередь.
4. Прогресс выполнения по количеству завершённых проверок, «Остановить проверку», обобщённое сообщение о результатах/сбое. Никакой автоматической диагностики при входе в раздел.
5. Пять раскрываемых карточек: Источники, yt-dlp и медиа, Очередь загрузок, Хранилище, LaMa и редактор. Для каждой проверки показаны название без внутренних ID, достоверный статус, пояснение, время и рекомендация, если есть.
6. Отдельный журнал неисправностей: состояния ACTIVE / NEEDS_RECHECK / RESOLVED, русские пояснения и рекомендации, количество повторов и время. Ограничение отображения до 20 последних записей. Очистка только после подтверждения и не касается AppLog.
7. Сведения об устройстве. ABI, поддерживаемые устройством, не называются ABI установленного APK.

### Конфиденциальность

При сетевом согласии поясняется возможность раскрытия внешнему серверу IP/VPN. В проверку НЕ отправляются cookies, токены, поисковые запросы, фотографии, видео и MP3.
Динамические URL, внутренние коды и секреты не отображаются. Сетевые пробы из этапа 3 заблокированы без согласия координатором независимо от UI.

### Сохранение

`RecentDiagnosticRunStore` сохраняет только последний **завершённый** `DiagnosticRun`, с помощью `AtomicFile`, по пути `filesDir/diagnostics/latest-run-v1.json`. Схема версионирована, файл ограничен 128 КиБ, коды проверок сверяются с актуальным реестром, данные проходят доменную валидацию. Устаревшая или повреждённая информация не объявляется успешной.

Новый `DiagnosticJournalRunner` сохраняет структурированные инциденты независимо от технического журнала, не запускается автоматически. Отменённый запуск не обновляет хранилища как завершённый. Ошибки чтения или записи показываются без публикации текста исключения и без удаления существующей истории.

### Ограничения этапа

- Нет экспорта приватного диагностического отчёта (этап 7).
- Не реализован переход к конкретной записи исходного AppLog: в старом техническом журнале ещё нет гарантированных стабильных ID всех событий, не изображаем неработающий переход.
- Наличие yt-dlp/FFmpeg/cookies, HTTP 200 и метаданные SAF не доказывают реальную загрузку или успешную запись файла, интерфейс показывает точные ограничения локальных проверок.
- Проверка поведения экрана на физическом Android, разных размерах и темах — при интеграционной приёмке; CI не заменяет эту проверку.
- Источники, движки скачивания, старый AppLog и подпись не изменялись.

## Проверки

- JVM: сохранение/восстановление последнего результата, отказ при изменении кода проверки, повреждённом коде причины/версии, сохранение `UNCHECKED` для пропущенной сети, восстановление HTTP 403 как отказа документа, а не поломки загрузчика.
- JVM: безопасные пользовательские названия источников (без HitMoz/Muzmo), различие «Не проверено» и «Не удалось подтвердить».
- CI: unit tests, Android lint, ARM64 assembleRelease, версия/ABI и исходные JS-тесты HitMoz/Muzmo.

После успешного CI отчитаться о результатах и остановиться перед этапом 7.
